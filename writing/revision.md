# 修订流程

> 写新章节有流程，改已有章节也要有流程。
> 修订不是"回头改几个字"，是有系统地确保修改不引入新问题。

---

## 什么时候需要修订

| 触发条件 | 修订类型 |
|---------|---------|
| 自审发现逻辑错误 | 强制修订 |
| 读者反馈某个场景无聊 | 建议修订 |
| 后续情节需要调整前文铺垫 | 强制修订 |
| 发现禁用词/去AI味问题 | 强制修订 |
| 想优化某个场景的描写 | 建议修订 |

---

## 修订流程

### Step 1：定位问题

```
问题章节：vol1-ch{XXX}
问题类型：逻辑错误/节奏问题/人物不一致/伏笔遗漏/去AI味
问题描述：{具体说明}
```

### Step 2：影响分析

```
直接影响：ch{XXX} 本身的 {具体段落}
间接影响：ch{XXX+1} ~ ch{XXX+N} 是否引用了错误设定？
涉及的伏笔：{F-ID列表}
涉及的角色：{C-ID列表}
涉及的时间线：{时间段}
```

### Step 3：制定修改方案

```
修改内容：{具体改什么}
修改范围：{只改这一章？还是需要连带改后续章节？}
风险评估：{改了之后会不会引入新问题？}
```

### Step 4：执行修改

1. 修改正文
2. 重新自审（`writing/critic.md`）
3. 更新受影响的持久化文件
4. 更新 `persistent/index.md`（如有ID变化）

### Step 5：验证

- [ ] 修改后的章节通过自审
- [ ] 后续章节不受影响（或已连带修改）
- [ ] 伏笔系统一致
- [ ] 时间线一致
- [ ] 角色状态一致

### Step 6：记录

在 `persistent/monitor.md` 的预警日志中记录修订。

---

## 修订优先级

| 优先级 | 类型 | 处理方式 |
|--------|------|---------|
| P0 | 逻辑错误（影响后续剧情） | 立即修订 |
| P0 | 伏笔遗漏（该埋没埋） | 立即修订 |
| P1 | 人物不一致 | 当章写完后修订 |
| P1 | 时间线错误 | 当章写完后修订 |
| P2 | 节奏问题 | 下一章写作前修订 |
| P2 | 去AI味问题 | 下一章写作前修订 |
| P3 | 描写优化 | 有空再改 |
