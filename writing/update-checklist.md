# 每章更新清单

> ⚠️ 写完一章后，按本清单逐项更新。
> 更新有依赖顺序——先更新基础数据，再更新衍生数据。
> 如果中断，下次写之前先检查哪些文件是旧的。

---

## 更新顺序（有依赖关系）

```
1. timeline.md          ← 时间是基础，其他模块依赖它
        │
        ▼
2. protagonist.md       ← 主角状态，依赖时间线
        │
        ▼
3. cast.md              ← 其他角色，依赖主角关系
        │
        ▼
4. foreshadow.md        ← 伏笔，依赖情节推进
        │
        ▼
5. index.md             ← 索引，依赖以上所有
        │
        ▼
6. monitor.md           ← 主线，依赖以上所有
        │
        ▼
7. reader-journey.md    ← 读者体验，依赖以上所有
        │
        ▼
8. dashboard.md         ← 仪表盘，依赖以上所有（最后更新）
```

**原则：如果中断，只完成了前3步，下次写之前检查第4-8步是否需要补上。**

## 每步详细检查

### Step 1：timeline.md
- [ ] 新增时间条目
- [ ] 时间是否连续？（和上一章的时间间隔）
- [ ] 异世界时间是否按换算规则计算？

### Step 2：protagonist.md
- [ ] 更新"当前状态"区（身体/心理/战力/物品/目标）
- [ ] 更新"最近三章事件"表
- [ ] 更新关系表（如有变化）
- [ ] 更新性格维度（如有变化）
- [ ] 更新技能树（如有新技能）
- [ ] 更新携带物品（如有新物品）

### Step 3：cast.md
- [ ] 更新出场角色状态
- [ ] 更新关系矩阵（如有变化）
- [ ] 新角色是否已添加？

### Step 4：foreshadow.md
- [ ] 新伏笔是否已添加？
- [ ] 推进的伏笔是否已更新状态？
- [ ] 回收的伏笔是否已标记🟢？
- [ ] 伏笔编号是否符合命名规范？

### Step 5：index.md
- [ ] 新ID是否已登记？
- [ ] 已有ID状态是否正确？

### Step 6：monitor.md
- [ ] 主线节点状态是否更新？
- [ ] 是否偏离计划？（偏差预警）

### Step 7：reader-journey.md
- [ ] 读者情绪曲线是否标记？
- [ ] 子线是否有推进？（断线预警）
- [ ] 节奏热力图是否标记？

### Step 8：dashboard.md
- [ ] 主线进度更新
- [ ] 伏笔健康更新
- [ ] 子线健康更新
- [ ] 节奏健康更新
- [ ] 预警日志更新（如有）

## 依赖检查表

当更新某个模块时，检查是否需要同步更新其他模块：

| 改了什么 | 必须检查 | 必须更新 |
|---------|---------|---------|
| timeline | plot时间逻辑 | 无 |
| protagonist性格 | cast关系、后续节拍 | protagonist快照 |
| protagonist关系 | cast关系矩阵 | 双方档案 |
| cast角色状态 | protagonist关系表 | 双方档案 |
| foreshadow状态 | plot对应节拍 | index |
| monitor偏离 | plot后续节拍 | monitor |
| reader-journey节奏 | plot后续节拍 | reader-journey |

## 故障恢复

如果发现之前的章节有逻辑错误：

### Step 1：影响分析
```
错误发生在：vol1-ch{XXX}
影响范围：ch{XXX} ~ ch{XXX+N}（检查后续章节是否引用了错误设定）
涉及的伏笔：{F-ID列表}
涉及的角色：{C-ID列表}
涉及的时间线：{时间段}
```

### Step 2：修复顺序
```
1. 修正错误章节的正文
2. 修正 timeline.md（如有时间错误）
3. 修正 protagonist.md（如有状态错误）
4. 修正 cast.md（如有角色错误）
5. 修正 foreshadow.md（如有伏笔错误）
6. 修正 index.md（如有索引错误）
7. 修正 monitor.md（如有进度错误）
8. 修正 reader-journey.md（如有节奏错误）
9. 修正 dashboard.md（最后）
10. 检查后续章节是否需要连带修正
```

### Step 3：记录
在 `monitor.md` 的预警日志中记录：
```
| 时间 | 章节 | 类型 | 描述 | 处理 |
|------|------|------|------|------|
| {日期} | ch{XXX} | 逻辑错误 | {描述} | 已修正ch{XXX}~ch{XXX+N} |
```
